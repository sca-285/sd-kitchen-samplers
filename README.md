# Kitchen Samplers

Extra samplers and schedule types for **Forge**, **reForge** and **Forge Classic (Neo)**. Each algorithm is offered once.

This repository includes third-party sampler and scheduler code. It is **not affiliated with** Extra Samplers, RES4LYF, reForge or Forge Classic. Sources and licenses: [NOTICE.md](NOTICE.md).

On start-up the extension compares its list with the WebUI:

- If the WebUI already has the algorithm, that version is kept. Nothing is added or replaced.
- If the WebUI lacks it, the missing sampler or schedule is registered.
- Names used by the other WebUIs become aliases, so PNG info written on one WebUI pastes into another.

There is no panel on txt2img or img2img. Pick a sampler or schedule type in the usual dropdowns. The few options live under **Settings → Kitchen Samplers**.

This is not a replacement for [MisterChief95's Extra Samplers](https://github.com/MisterChief95/sd-forge-extra-samplers), and it is not affiliated with that project. Extra Samplers' unique algorithms are included here, with credit, so one extension can cover Forge, reForge and Neo. Do not enable both: they register the same samplers. See [NOTICE.md](NOTICE.md) for sources and licenses.

## What each WebUI gets

| | Forge | reForge | Neo |
|---|---|---|---|
| Samplers added | 84 | 62 | 84 |
| Already in the WebUI, kept as its own | 6 | 28 | 6 |
| Schedule types added | 13 | 4 | 14 |
| Settings added (only what this WebUI lacks) | 34 | 5 | 41 |

Every WebUI ends up with all 90 sampler entries and 29–31 schedule types, Automatic included. Neo also keeps its flow-only FlowMatch and Flux2.

## Install

Clone this repository into `extensions/`, or use **Extensions → Install from URL**. Then restart the WebUI.

If [sd-forge-extra-samplers](https://github.com/MisterChief95/sd-forge-extra-samplers) is installed, disable it. The console warns if it is still enabled.

### Settings from Extra Samplers

Extra Samplers had an always-visible **Extra Samplers** accordion. Those controls now live in **Settings → Kitchen Samplers**. The keys were kept (`exs_ap_*`, `exs_langevin_strength`), so values saved in `config.json` carry over. PNG info written by Extra Samplers still pastes.

## Settings and X/Y/Z

**Settings → Kitchen Samplers** lists only options that do something on the running WebUI and that it does not already define:

- the tuning of Adaptive Progressive and Langevin Euler;
- the options of a WebUI sampler or schedule type copied in here. For example, HeunPP2's `s_churn` on Neo.

reForge already has most of these under the same names, so there it shows only five.

Each of these options is also an X/Y/Z axis, named `[Kitchen] <setting>`. Values go through `override_settings`, so nothing stays changed after the plot.

## Fixes

Each fix below is covered by a test. [NOTES.md](NOTES.md) has the measurements.

### reForge

- Its own samplers (DEIS, SEEDS, Gradient Estimation, …) silently switched **any schedule type not in their hard-coded table** to Normal. Beta 57, Linear Log, Bong Tangent and Linear Quadratic now work with them.
- **Sinusoidal SF, Invcosinusoidal SF and React Cosinusoidal DynSF** returned one sigma short with no final 0, unlike reForge's other copy of the same functions. They now end on 0, so you get the step count you asked for. Without the final 0, DEIS and DDPM produced NaN.

### Align Your Steps 11 / 32 / GITS

The last table entry was an absolute 0.029. On flow models the schedule climbed back up before the end. It is now a ratio of sigma_max like the other entries, and unchanged on SD 1.x and SDXL.

### From Extra Samplers

- **Euler Multipass CFG++** read `model.last_noise_uncond`, which Neo does not have. It now takes the uncond prediction from a post-CFG hook, which works on all three WebUIs.
- **Heun Ancestral** built its own unseeded noise, so the same seed gave a different image. It now uses the WebUI's seeded noise.
- **Adaptive Progressive and Langevin Euler** read their settings from the accordion. They now read Settings, and the values are written to the infotext.

### Prompt-schedule counts

RES4LYF abnorsett_3m and 4m spend 4 and 9 extra model calls starting up. These now count toward total steps, so `[a:b:0.5]` switches at the right step.
